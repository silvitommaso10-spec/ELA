# M0.2 — CI e template di milestone

- **Stato:** Implementata
- **Riferimenti spec:** §51, §53
- **Branch:** `claude/ela-bootstrap-m0-1-ymk75r`

## Obiettivo

Rendere `make check` un vincolo automatico su ogni push e pull request, e dare a ogni
milestone una forma unica e verificabile, così che la disciplina di §53 (SPEC →
IMPLEMENTATION → TEST → REVIEW → COMMIT) sia controllata dal repository e non solo dal
prompt.

## In scope

- `.github/workflows/ci.yml`: su push e pull request esegue `uv sync --locked` e
  `make check` su ubuntu-latest e macos-latest con Python 3.12; cache di uv basata su
  `uv.lock`; i run sovrapposti sullo stesso ref vengono cancellati.
- `docs/milestones/TEMPLATE.md` con le sezioni Obiettivo, In scope, Out of scope, Criteri di
  accettazione, Test previsti, Rischi, Domande aperte.
- `docs/milestones/M0.1.md` riscritta sul template; questo documento.
- `scripts/check_milestone.py`: fallisce se una milestone in `docs/milestones/` (template
  escluso) non ha la sezione "Criteri di accettazione" o la ha vuota o con soli segnaposto.
  Nuovo target `milestones` nel `Makefile`, incluso in `check`.
- `tests/scripts/test_check_milestone.py`: comportamento pass/fail dello script.

## Out of scope

- Badge, release, pubblicazione di pacchetti, job su Windows.
- Esecuzione di pre-commit in CI (ruff, mypy e detect-secrets girano già in `make check`
  o localmente).
- Verifica delle altre sezioni del template: solo i criteri di accettazione sono obbligatori.
- Codice di dominio.

## Criteri di accettazione

- `make check` passa in locale e include il target `milestones`.
- Il workflow CI esegue `make check` su ubuntu e macos con Python 3.12 e cache uv, e parte
  su push e pull request.
- `uv run python scripts/check_milestone.py` esce con 0 sul repo e con 1 se una milestone
  ha i criteri di accettazione mancanti o non compilati.
- `M0.1.md` e `M0.2.md` seguono le sezioni di `TEMPLATE.md`.

## Test previsti

- `tests/scripts/test_check_milestone.py` — milestone valida passa; sezione mancante, vuota
  o con soli segnaposto fallisce; il template viene ignorato.

## Rischi

- Il primo run del workflow avviene solo dopo il push: la sintassi YAML è verificata in
  locale, ma il comportamento dei runner (macos in particolare) si osserva sulla PR.
- `uv sync --locked` fallisce se `uv.lock` non è aggiornato: è voluto, forza a committare il
  lock insieme a `pyproject.toml`.

## Domande aperte

- Nessuna.
