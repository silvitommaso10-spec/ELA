# M0.1 — Bootstrap del repository

- **Stato:** Implementata (review fix applicate il 2026-09-04)
- **Riferimenti spec:** §48, §49, §52, §53, §54
- **Branch:** `claude/ela-bootstrap-m0-1-ymk75r`

## Obiettivo

Preparare il repository ELA con specifica, struttura, tooling di qualità e un primo
architecture test, senza scrivere codice di dominio, così che ogni milestone successiva parta
da `make check` verde.

## In scope

- `docs/spec/ELA_spec.md`: conversione di `ELA.pdf` (70 sezioni, numerazione preservata,
  diagrammi e alberi in blocchi verbatim, i quattro titoli spezzati dal PDF riuniti).
  `ELA.pdf` conservato accanto come originale; script di conversione one-off in
  `scripts/pdf_to_spec.py` con PyMuPDF nel gruppo `dev`.
- `CLAUDE.md` dal testo di `claude.md.pdf` (eliminato), con la regola commit/push sul branch
  di lavoro e mai merge su `main` né `--force`.
- Struttura di cartelle di §48: sottopackage di `src/ela` con `__init__.py` vuoto,
  `domain.py` e `ports.py` con la sola docstring, README di una riga con fase
  (`v0.1` / `post-0.1`) e sezioni della spec nelle cartelle senza codice.
- Progetto uv con Python 3.12, `uv_build`, dipendenze solo nel gruppo `dev` (pytest,
  pytest-cov, hypothesis, ruff, mypy, import-linter, pre-commit, detect-secrets, pymupdf).
- Configurazione: ruff, mypy `--strict` su `src/`, pytest con branch coverage su `ela`,
  contratti import-linter (domain/ports non importano providers/api/tools; il Core non
  importa anthropic, openai, sqlalchemy, fastapi, httpx), pre-commit con ruff, mypy e
  detect-secrets, `.gitignore` con `.env`, `.env.example` vuoto.
- `docs/adr/README.md` (template e indice) e `docs/adr/0001-stack.md`.
- `Makefile` con `install`, `lint`, `typecheck`, `test`, `check`.
- `tests/architecture/test_layers.py` e `tests/docs/test_spec_headings.py`.

## Out of scope

- Classi, entità, port, tool, provider, configurazione: `domain.py` e `ports.py` vuoti.
- Dipendenze runtime (nemmeno pydantic finché `domain.py` è vuoto).
- CI, Dockerfile, migrazioni.
- Pull request e merge su `main`: il merge lo fa l'utente dopo revisione.

## Criteri di accettazione

- `make check` passa: ruff check e format puliti, contratti import-linter rispettati, mypy
  strict senza errori, pytest verde con report di coverage su `ela`.
- `docs/spec/ELA_spec.md` contiene i 70 heading `## 1.` … `## 70.` in ordine, nessuno vuoto
  o tronco; `uv run python scripts/pdf_to_spec.py` lo rigenera identico.
- L'albero del repo corrisponde a §48, più `docs/{spec,adr,milestones}` e
  `tests/{architecture,docs}`.
- `.env` è ignorato da git; `detect-secrets scan` non trova segreti.

## Test previsti

- `tests/architecture/test_layers.py::test_domain_imports_only_stdlib_and_pydantic` —
  `domain.py` esiste, il suo AST importa solo stdlib o pydantic, è importabile. Verificato in
  negativo con `import yaml`.
- `tests/docs/test_spec_headings.py::test_spec_has_70_numbered_sections_with_complete_titles`
  — 70 heading ordinati, titoli completi, i quattro titoli riuniti (§8, §36, §58, §65).

## Rischi

- La conversione PDF → Markdown dipende dal layout estratto da PyMuPDF: lo script fallisce
  esplicitamente se il conteggio delle sezioni o dei titoli riuniti cambia.
- I contratti import-linter sono banalmente rispettati finché non c'è codice: diventano
  significativi dalle milestone con dominio.

## Domande aperte

- Nessuna. Decisioni prese in review: `src/ela/executive` è v0.1 (ospita l'executor della
  pipeline §27); `context`, `memory`, `evolution` restano post-0.1; `identity` è v0.1 (§54).
